# Re-baselining Benchmark V2

A baseline is a single compiler identity measured on three linked surfaces:

- probe development evidence;
- canonical development evidence;
- canonical qualification monitoring evidence.

It also contains a checksummed snapshot of the exact compiler source boundary, non-engine `LR_*` environment, and optimized WASM artifact, plus the complete decision-code and validated-calibration fingerprints. Replay removes ambient compiler files before extracting the snapshot and installs its lockfile with `npm ci`; it never shares candidate sources or dependencies. Milestone canonical scores document the compiler of record; future promotion decisions execute this snapshot again on a fresh declared seed epoch under exactly the frozen decision contract.

Do not hand-edit baseline scores or pointers.

## Human Review

Generate click tracks and refresh the tracked template with
`npm run benchmark:v2:listening-template`. Complete every judgment in
`benchmark/v2/evidence/listening-review.json`, identify the human reviewer, add an ISO
timestamp, and copy the exact attestation printed in the file. Do not consult compiler or
qualification outcomes while reviewing. `prepare` validates pending templates, but
`baseline` and `canonical` require an approved review.

The generated clicks and complete V2 timelines can be reviewed together at
`/spec-dashboard/?collection=v2` while `npm run dash` is running. The dashboard is a
review surface only; approval remains the explicit tracked attestation below.

Approval also requires every `item.audio` file to exist and match both its recorded SHA-256
and deterministic regenerated bytes. On a clean checkout with an already approved review,
run `npm run benchmark:v2:clicks` to recreate those exact generated WAV files without
overwriting the tracked review.

## Create

```bash
npm run benchmark -- baseline --label=NAME
```

The command verifies the approved listening review and current calibration, freezes the decision contract before execution, verifies that the state transition is legal, snapshots the compiler, prepares the typed catalog, runs the probe, runs canonical development and qualification, rejects any mid-run decision-contract change, verifies complete worker-success scope and snapshot identity, retains compressed archives under `benchmark/v2/runs/`, writes a combined baseline bundle, and regenerates:

- `benchmark/v2/baseline.json`
- `docs/benchmark-v2-baseline.md`
- `benchmark/v2/confirmation-state.json` with one available canonical attempt

Use `--resume` after an interrupted run with the same label. Use `--jobs=N` to reduce host pressure.

## Verify

```bash
npm test
npm run benchmark -- prepare
sha256sum -c benchmark/v2/runs/LABEL-*.json.gz.sha256
```

Check that archive and compressed hashes match the baseline reference, every archive records the approved listening-review fingerprint, raw reports rescore exactly, probe/canonical actual seeds do not overlap at 250k or 500k, and confirmation state is `available`. Do not spend the one canonical slot on a self-comparison.

Within the same suite, rebaseline is permitted only when the prior result is `accept` and the working compiler identity is the accepted candidate. `reject` and `inconclusive` consume the attempt and cannot be bypassed by rerunning `baseline`. An intentionally changed suite fingerprint starts a new contract and may establish its initial baseline. Seed epochs remain in the ledger across either transition.

## When Required

Establish a new baseline after intentionally changing any of:

- typed cases, catalog membership, parents, groups, strata, or weights;
- scoring, measurements, target interpretation, or transform;
- budgets, seed counts, seed ranges, or profile authority;
- engine artifact or semantic execution protocol;
- decision thresholds, critical levels, promotion semantics, inference code, or calibration evidence;
- the promoted compiler of record.

An operational-only runner change is incomparable by default. It may retain semantic comparability only through a reviewed suite-specific entry in `benchmark/v2/runner-compatibility.json` backed by checksummed bit-identity evidence.

The archived V1 procedure is `archive/REBASELINE_V1.md`.
