Forward-Eval / Rollout — Logic Map

How the handoff compiler ranks candidate arcs at each gap, with the FULL leaf and SHORT (objective) leaf spelled out side by side. File:line anchors throughout (all in scripts/v0/optimizer/handoff.ts unless noted). This is the artifact to verify against the code.

0 · Where this sits

The compiler builds a track gap by gap with a stack-based, best-child-first DFS (runFrontier, ~1095). At each node it must pick which candidate arc(s) to expand. Forward-eval is the ranker for that choice: above a budget gate it scores each candidate by the true forward value of where the arc leads — a charged greedy:2 rollout — instead of a local proxy. The rollout's terminus is scored by a leaf scorer, which is the FULL re-detection (default) or the SHORT objective value (the experiment).

2 · Stage ① — Pool generation node.ts:97

getCandidatesSorted(node, gaps, ctx, seed, nCand):
  gap = gaps[node.gapIndex]
  if not gap.endsWithContact: return []          # non-contact gap → no catch to place
  rng = makeRng(hash(seed, node.gapIndex))        # per-gap RNG; independent of budget
  samples = solveOneGap(node.prefixEngine, gap, rng, nCand, ...)   # nCand arcs that LAND the contact
                                                   # (gate-passed: catch within ±1 frame, on the gap's lines, alive)
  sorted = sortCandidatesByCost(samples)           # (a) cost order = aggregate axis-L2 error
  if LR_RANK_QUALITY (default ON):
      sorted = sortCandidatesByQuality(...)         # (b) re-sort by the QUALITY OBJECTIVE:
                                                    #     axisQuality(achieved) × scoreNextGapReadiness   (objective.ts:60)
  if nCand > 1 and aim-lane enabled:
      laneExtras = enumerativeProposer(top-K bases) # (c) LR_AIM_TOPK_BASES=3: model-proposed arcs,
      sorted = merge_and_requalify(sorted, laneExtras)#     compete on cost/quality like any sample
  return sorted
Critical for the rollout: the rollout interior calls this with nCand = branch = 1 (greedy). With nCand = 1 the quality re-sort is a no-op (one item) and the aim lane never runs (nCand > 1 guard, node.ts:183). So inside a rollout, each downstream contact is the first viable sample — no ranking, no aiming. The pool at the top level (step ②) uses a budget-aware nCand (budgetAwareContractSampleCount/handoffSampleCount, bounded by HANDOFF_CONTRACT_N_CAND=14) and is quality-sorted before forward-eval re-ranks it. The aim-lane K (LR_AIM_TOPK_BASES=3) itself collapses to 1 below a maturity budget (aim.ts:231).

3 · Stage ② — Candidate ranking :2098 / :2843

rankedOptions(node, ...):
  pool   = getCandidatesSorted(node, nCand=budgetAware ≤ HANDOFF_CONTRACT_N_CAND=14)[0:poolSize]  # quality-top pool
  scored = [ scoreCandidateForHandoff(c, "pool") for c in pool ]
  scored += [ scoreCandidateForHandoff(c, "reuse") ]   # catch-reuse extras (periodic-rhythm translate)
  scored += [ scoreCandidateForHandoff(c, "brake") ]   # uphill brake-catch extras (shed speed)
  scored.sort( by score↑, then candidate.cost↑, then rank↑ )
  return scored[0 : HANDOFF_BRANCHING]                  # these become the DFS children

scoreCandidateForHandoff(node, candidate, ..., targetBudget):
  child = extendNodeCached(node, candidate)              # commit the arc onto the prefix engine
  if fwdEvalCfg != null AND usesForwardEvalAtBudget(node, targetBudget):   # :3930
      #  targetBudget ≥ LR_FWD_EVAL_MIN_BUDGET (75k) → always;  below → stochastic ramp
      value = forwardArcValue(child, ..., matureForwardEvalConfig(fwdEvalCfg, node, gaps, targetBudget))
      return { score: -value }            # higher rollout value ⇒ more-negative score ⇒ sorts first
  else:                                    # LOCAL PROXY (below the gate, :2893)
      preview  = previewFutureContacts(child, ...)             # K=1 survivor preview
      scarcity = (firstSurvivors==0) ? DEAD_END_PENALTY(40) : SURVIVOR_SCARCITY(4)/firstSurvivors
      score    = cost + (scarcity + previewCost·0.25)·previewScorePressure
                      + handoffStatePenalty + overshootPenalty + releaseSetupPenalty

Note: score is minimized. The forward path returns −value so the highest-rollout-value arc sorts first. The proxy path returns a positive cost-like score. Within one compile every pool member uses the same branch (budget gate is per-node, not per-candidate), so forward-eval scores never mix with proxy scores inside one pool — except that reuse/brake extras at the same node also pass through the same gate.

4 · Stage ③ — The forward rollout :3889 / :3774

forwardArcValue(child, ..., cfg):                       # cfg = {variant, depth, branch, charge, leaf}
  saved = simFrames()
  rootGapIndex = child.gapIndex - 1                       # the candidate's OWN gap (the always-differing factor)
  ownGapImpact = trueTargets[rootGapIndex].impact
  leafObjective = (cfg.leaf == "objective")
                  AND NOT (hybridImpact AND ownGapImpact ≥ 0.35)   # hybrid: impact gaps use FULL leaf
  value = (cfg.variant=="avg") ? forwardAvgNextScore(child, ..., cfg.branch, leafObjective, rootGapIndex)
                               : forwardRolloutScore(child, depth=cfg.depth, branch=(best?cfg.branch:1), ...)
  charge (simFrames()-saved) to the budget    # honest; refunded iff LR_FWD_EVAL_CHARGE=0
  return value

forwardRolloutScore(search, depthLeft, branch, leafObjective, rootGapIndex):   # greedy: branch=1, depth=2
  if depthLeft ≤ 0 or terminal(search):  return leafValue(search, missed=0)
  at = advanceToNextContact(search)                       # walk to the next contact gap
  if at == null:                          return leafValue(search, 0)
  atBranch = (impactBranch>1 and gaps[at].impact≥0.35) ? max(branch,impactBranch) : branch  # LR_FWD_EVAL_IMPACT_BRANCH, default 1=off
  cands = getCandidatesSorted(at, nCand=atBranch)          # branch=1 ⇒ first viable sample (no aim, no rank)
  if cands is empty:                                       # DEAD-END: cannot place the next contact
      missed = min(PARTIAL_FUTURE_CONTACT_WINDOW=20, remainingContactGaps(at))
      return leafValue(search, missed)                     # mirror the full leaf's missing penalty
  best = -inf
  for c in cands:                                          # branch=1 ⇒ exactly one
      best = max(best, forwardRolloutScore(extend(at,c), depthLeft-1, branch, ...))
  return best

leafValue(node, missed):
  if leafObjective:  return objectiveLeafValue(node, rootGapIndex, gaps, missed)   # ④-SHORT
  else:              return forwardNodeScore(node, gaps, ctx)                       # ④-FULL
                     # (shadow: ranks by FULL but also records objectiveLeafValue for telemetry)

Variants (LR_FWD_EVAL, default greedy:2): greedy = single deepest rollout (branch 1); best = max over branch next-contact alternatives; avg = mean over top-m, 1 deep. matureForwardEvalConfig (:3952) may upgrade to avg:1 (depth 2, branch 1 — MATURE_AVG_FWD_EVAL_BRANCH=1, :472) on amplitude/elevation gaps at high budget. Start-selection runs a SEPARATE charged greedy:2 over the initial-condition candidates (startForwardScore :3604), always FULL leaf — historically +32.5 headline, so it is its own consequential ranking, not a footnote.

5 · Stage ④ — The leaf scorers (the heart of it)

FULL forwardNodeScore :3553

forwardNodeScore(search, gaps, ctx):        # :3553
  if isTerminalNode(search):                # FULL-track leaf
     horizon = durationFrames; outDur = dur+20
     report  = rawReport       # NO asPartialReport
  else:                                     # PARTIAL leaf (usual rollout case)
     horizon = processedHorizonFrame(search)   # :4664
             = endFrame of LAST committed contact gap
     outDur  = min(durationFrames, horizon + 20)
             # ride out ONLY ~20 frames past last contact
     report  = asPartialReport(raw, horizon)    # :4678
  det = detectWindow(search.prefixEngine, 0, outDur)
        # RE-DETECT whole composed track from frame 0
        # (prefix frames CACHED in the fork — only new
        #  frames re-simulate)
  raw = buildDriftReport(det, ...)            # substrate.ts:650
  return scoreDriftReport(report).full_score  # the TRUE scorer (5 factors)
asPartialReport(report, horizon):            # :4678
  reached = contacts t_target ≤ horizon
            (keep detected status hit/drift/missing)
  future  = contacts t_target > horizon,
            first 20, ALL marked "missing"
  gaps & off_beat_landings ALSO filtered to ≤ horizon
    ⇒ axis_quality's combined-RMS spans ONLY gaps
      ending ≤ horizon  (bears on §9 axis lever)
  terminus.frame = min(actual, horizon)
  endOfSpec → remapped to "rideStalled"

SHORT objectiveLeafValue :3630

objectiveLeafValue(leaf, gaps, durationFrames):  # :3630
  # FAITHFUL reconstruction of the true scorer from
  # the rollout's OWN committed fits, zero engine.
  errors = []; missingFit = 0
  for i in [0, leaf.gapIndex):          # WHOLE prefix,
    if not gaps[i].endsWithContact: continue   # not just
    fit = leaf.prefixFits[i]                   # the rolled span
    if fit == null: missingFit++; continue
    a = fit.achievedAtEnd ?? fit.achieved      # GAP-window axes
    errors += axisErrorsForTargets(trueTargets[i], a)  # scorer's window
  value = 1000 × axisQualityFromErrors(errors).axis_quality
          # ONE combined RMS over the whole prefix — the
          # full leaf's own fold (RMS is non-linear ⇒ the
          # prefix does NOT cancel: lets the score ABANDON
          # an over-sped prefix). NO readiness, NO hybrid.
  if missingFit > 0: value *= e^(-missingFit)
  horizon  = processedHorizonFrame(leaf)         # last committed contact
  survival = isTerminalNode(leaf) ? 1            # reachedEnd ⇒ 1
             : clamp01(horizon / durationFrames) # else depth proxy
  futureMissing = min(20, remainingContactGaps(leaf.gapIndex))
  value *= survival × e^(-futureMissing / MISSING_CONTACT_TOLERANCE)
  return value

Scores each committed fit's achievedAtEnd axes — the gap window [start, endFrame], the SAME window the true scorer measures (pure engine, computed once at fit time; falls back to the lookahead achieved only when the windows coincide). Zero engine frames at leaf time. The axis RMS spans the whole committed prefix [0, leaf.gapIndex) — same fold as the full leaf; survival (terminal ⇒ 1, else depth proxy) × missing read off the rollout's committed depth. Readiness/hybrid machinery deleted (bf49062): the leaf is exactly axis × survival × missing.

The SHORT leaf now reproduces all five factors EXACTLY, at zero engine frames: axis over the gap window (achievedAtEnd = the scorer's own window, residual 0 — commit 01d7af8), drift/off_beat = 1 (gate-enforced per gap), missing from committed depth (same structure), survival = 1 on terminal leaves (reachedEnd) / the clamped proxy on partials (which matches the full leaf — commit 589e801). It is a faithful reconstruction of the true scorer, ~21% cheaper per rollout — and is now the default.

6 · The true scorer score.ts:237

full_score = 1000
  × axis_quality      # exp(-rms(all axis errors over all landed contacts) / AXIS_QUALITY_TOLERANCE=0.25)
  × drift_quality     # exp(-rms(landed_excess beyond ±1 frame)         / SYNC_TOLERANCE)
  × missing_quality   # exp(-missing_count                              / MISSING_CONTACT_TOLERANCE=1.0)
  × off_beat_quality  # exp(-off_beat_landings                          / OFF_BEAT_TOLERANCE=1.0)
  × survival_quality  # reachedEnd ? 1 : clamp01(terminus.frame / total_frames)
# contract_passed = (drift==0 and missing==0 and off_beat==0 and not died)

7 · Pool → children → DFS :2203 / ~1095

  • Sort key: score↑, candidate.cost↑, rank↑. The leaf score's ONLY job is (a) which top-HANDOFF_BRANCHING children survive, and (b) their explore order.
  • Frontier: two LIFO stacks (passStack / fallbackStack). enqueueChild (:1477) routes by skippedContacts; no score thresholding. runFrontier pops, expands, pushes children (best last → popped first) → depth-first, best-child-first. A "far-back pulse" occasionally pops an older branch by gap-lag (not score).
  • Completion / acceptance uses the REAL scorer on the finished track, not the leaf score.

9 · Status & the evidence scripts

The catastrophic collapse (objective leaf → drums_crescendo 0/10) is solved and committed (bf49062): the combined-RMS-over-the-whole-prefix × survival × missing reconstruction brought drums_crescendo and solo_run to parity with the full leaf at ~21% fewer rollout frames. The lone residual — big_air_ramp — was then closed by scoring the axis over the gap window the scorer uses, not the lookahead window (01d7af8), and terminal survival now reproduces reachedEnd = 1 (589e801). The objective leaf is now an exact reconstruction of the true scorer and ~21% cheaper per rollout, so across all 40 golden specs it beats the full leaf by +1.72 (decide ACCEPT, zero regressions, big_air +2.4) — and is now the default. See docs/short-leaf-campaign.md for the goal and the evidence scripts below.

The empirical evidence is in a suite of standalone scripts (all under scripts/v0/); each isolates one layer of the short-vs-full question. Run any with LR_ENGINE=wasm npx tsx scripts/v0/<name>:

  • eval_short_leaf.sh — the headline: short-leaf golden vs a one-time full-leaf baseline + decide, with per-track×budget and per-axis/factor summaries. This is the target metric.
  • eval_arc_apples.ts — per-arc, same rider state: short (ballistic) vs full (engine) achieved + leaf-ranking agreement. Isolates measurement from search divergence.
  • eval_pergap_vs_composed.ts — on one committed track, each gap's ballistic achieved vs the composed-engine measurement, per axis.
  • eval_leaf_factors.ts — per offered node, the short leaf's reconstructed factors (axis/drift/off_beat/missing/survival) vs the full leaf's measured ones.
  • eval_ballistic_vs_engine.ts — frame-by-frame ballistic-predicted vy/y vs the engine, from the exact launch state (the airborne model's own error).
