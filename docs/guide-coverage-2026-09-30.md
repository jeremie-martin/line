# Improving intermediate guide choices and transferring to facets

The owner authorized diagnosis, bounded search improvements, fresh evaluation,
and transfer to one existing geometry. Normal lines remain mandatory. Benchmark,
detector, scorer and physics are frozen. Guide count remains an optional artistic
preference, not an aesthetic score or a new specification control.

## Protocol fixed before development

The previous study's seeds 241–248 are now exposed evidence. Development uses
the original six passages and seeds 241/242, at 450,000 and 900,000 total physics
frames. The control is the previous recommended balanced two-path search with
independent guided/unguided references, frozen at `0f0da680`.

The diagnostic questions are whether later guide permissions undo simplification,
whether useful intermediate alternatives receive further search, and how much
construction capacity is lost to redundant or underfunded attempts. Controlled
ablations will compare preserving later permissions, a frontier spanning the
measured accuracy/guide-count range, and their combination. Geometry is still
independently searched; preserving permissions does not reuse an unvalidated ride.

Select the candidate on development results, then freeze it before running
**seeds 271–278**. The confirmation panel contains the original six passages
plus three newly authored passages, defined in
`scripts/gallery/guide_confirmation_cases.ts` before development measurements:
offset cadence, rising pulse and long breath. Report reused and new passages
separately. Confirm at both total allowances. Run the same comparison on facets
using the existing geometry recipe (`subdivisions: 0.5`), with no shape-specific
tuning against confirmation results.

Keep the original common accuracy ceilings and guide caps. Report best accuracy,
feasibility, actual work, unsuccessful attempts, and per-passage losses. Seed-block
bootstrap intervals characterize this small panel, not broad musical generality.
No invented aggregate headline combines accuracy and guide count. No algorithm

The gallery should expose matched forks, independent references and complete

## Candidate frozen before confirmation

Development measured 168 portfolios across seven variants. The previous
recommended search reproduced all 24 control portfolios exactly: track hashes,
RMS errors and physics work. Three/four active paths improved some intermediate
guide caps but reduced best accuracy. Preserving source permissions also caused
accuracy losses; this is retained as an explicit experiment, not enabled by default.

The preselected candidate is **`focused`**, implemented in clean compiler
**`fc3023a2`**. It retains the most accurate path and the intermediate path that
most improves coverage of the measured error envelope between its accurate and
sparse endpoints. When there is no useful intermediate, it follows the sparse
endpoint. All complete alternatives remain available for delivery. Two active
paths retain the previous per-branch allocation scale. Later guides remain
allowed, exactly as in the control; no guide quotas or music rules are added.

Across the 12 development case/seed pairs at 900,000 frames, best RMS is
0.029703 versus 0.029747, and half-guide-cap RMS is 0.043222 versus 0.049706.
At 450,000, those values are 0.034918 versus 0.034847 and 0.049700 versus
0.052832. Quarter-guide coverage and guide count at some common error ceilings
worsen. This is a targeted tradeoff improvement, not uniform superiority.

Freeze these choices before inspecting confirmation seeds 271–278. Compare
`candidate` (the previous balanced search) with `focused` on all nine passages,
both allowances and both shapes: **576 portfolios**. Separate the six reused
passages from the three new passages. Do not tune against these results.

A separate diagnostic probe uses exposed quick-pickups seed 242 and
staccato-release seed 243. It varies continuation allowance and later guide
permissions from the same physical prefixes. That work is outside the matched
portfolio allowance and makes no portfolio-efficiency claim. Its initial source
selection incorrectly assumed a half-cap winner would contain a non-startup
guide; the corrected probe also handles a zero-guide winner. The aborted log is
retained with the completed measurements.
